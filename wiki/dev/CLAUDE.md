# wiki/dev/ — 개발 지식 베이스

이 폴더의 목적: **같은 실수를 두 번 하지 않는다.**

## 폴더 구조

### bugs/ — 버그 패턴 & 해결법
같은 에러를 또 디버깅하는 시간 낭비를 방지한다.

페이지 구조:
- `## 증상` — 뭐가 안 됐는가 (에러 메시지, 스크린샷)
- `## 원인` — 왜 났는가 (root cause)
- `## 해결` — 어떻게 고쳤는가 (코드 diff)
- `## 교훈` — 다음에 주의할 점, 재발 방지책

예시 파일명: `yfinance-rate-limit-403.md`, `supabase-stream-reset.md`

### design/ — UI/UX 디자인 결정
맘에 안 드는 디자인을 고칠 때, 왜 이렇게 만들었는지 기록이 없으면 또 같은 실수를 한다.

페이지 구조:
- `## 문제` — 뭐가 안 예뻤는가 (before 스크린샷)
- `## 개선` — 어떻게 바꿨는가 (after 스크린샷)
- `## 결정 이유` — 왜 이 디자인을 선택했는가
- `## 관련 컴포넌트` — 영향 받는 React 컴포넌트 목록

예시 파일명: `sector-card-layout.md`, `chart-color-scheme.md`, `mobile-responsive.md`

### architecture/ — 아키텍처 결정 기록 (ADR)
"왜 이렇게 만들었는가"를 기록. 리팩토링 시 맥락을 잃지 않기 위함.

페이지 구조:
- `## 결정` — 무엇을 결정했는가
- `## 대안` — 검토했던 다른 방법들
- `## 이유` — 왜 이걸 선택했는가
- `## 트레이드오프` — 이 결정의 약점

예시 파일명: `curl-cffi-over-requests.md`, `global-cache-strategy.md`

### api/ — API 설계
프론트-백 연동 규칙. 엔드포인트 변경 시 양쪽 동기화 누락 방지.

### crawling/ — 크롤링 패턴
yfinance, Naver, Google 뉴스 스크래핑 노하우. rate limit 회피, 파싱 전략.

### deployment/ — 배포 관련
Render 설정, 캐시 전략, 환경변수, 디스크 관리, 성능 최적화.

### lessons/ — 교훈 모음 (회고)
스프린트, 큰 버그, 리팩토링 후 배운 점을 모아두는 곳.
같은 카테고리의 교훈이 3개 이상 쌓이면 → bugs/ 또는 architecture/에 패턴으로 승격.

페이지 구조:
- `## 상황` — 무슨 일이 있었는가
- `## 배운 것` — 핵심 교훈
- `## 다음에는` — 구체적으로 뭘 다르게 할 것인가
